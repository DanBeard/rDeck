# Docker Setup for Maps Services

Provides offline map tiles, routing (Valhalla), and geocoding (Nominatim) for the rDeck companion server. Map data is downloaded from Geofabrik and processed locally — no API keys required.

## Quick Start

```bash
cd companion-server/docker

# 1. One-time setup: pick a region, download data, generate tiles
./setup.sh

# 2. Start services + companion server TUI
./run.sh
```

## How It Works

```
setup.sh                              run.sh
--------                              ------
1. Pick region (interactive menu)     1. Migrate old identity (one-time)
2. Download PBF from Geofabrik        2. Start Docker containers
3. Generate vector MBTiles             3. Launch companion server with --with-maps
   (Planetiler, one-shot)                (passes through extra args like --headless)
4. Copy tileserver config
5. Write .env
```

The PBF file is shared across all three services:
- **Valhalla** — routing engine, reads PBF directly
- **Nominatim** — geocoding, imports PBF into PostgreSQL
- **tileserver-gl** — renders vector MBTiles to raster PNG on demand

The companion server fetches rendered PNG tiles from tileserver-gl via HTTP, then dithers them for the e-ink display.

## Switching Regions

```bash
docker compose down
rm -rf data/valhalla data/nominatim data/mbtiles data/pbf
./setup.sh    # Pick new region
./run.sh
```

PBF files are kept in `data/pbf/` so you can switch back without re-downloading.

## Connecting the rDeck Emulator

The companion server uses the host's Reticulum config (`~/.reticulum/`). Use `--tcp-port` to auto-generate a config with a TCP server interface:

```bash
python -m companion_server --tcp-port 4242 --with-maps
```

Then in the rDeck emulator settings:
- TCP Host: `127.0.0.1`
- TCP Port: `4242`
- Enabled: `true`

## Data Layout

Companion server data (identity, trust, config) lives in `~/.companion-server/` by default, shared between `run.sh` and direct `python -m companion_server` invocations. Override with `--data-dir` or `COMPANION_DATA_DIR` env var.

Docker service data lives in `./data/` (gitignored):

```
~/.companion-server/    # Config, identity, trust state, LXMF storage
data/
├── pbf/                # Downloaded PBF files (shared by all services)
├── mbtiles/            # Vector MBTiles generated by Planetiler
├── tileserver/         # tileserver-gl config and style
├── valhalla/           # Routing tiles
└── nominatim/          # PostgreSQL geocoding database
```

## Services

| Service | Port | Purpose |
|---------|------|---------|
| tileserver-gl | 8081 | Renders vector tiles to PNG |
| Valhalla | 8002 | Turn-by-turn routing |
| Nominatim | 8080 | Address/place search |

## Stopping

- **Ctrl+C** stops the companion server TUI
- `docker compose down` stops all Docker services

## Resetting Data

```bash
docker compose down

# Reset everything
rm -rf data/

# Reset just companion server config/identity
rm -rf ~/.companion-server

# Reset map databases (triggers reimport on next start)
rm -rf data/valhalla data/nominatim data/mbtiles data/tileserver

# Keep PBF downloads (avoid re-downloading)
# data/pbf/ is preserved by the above
```

## Checking Service Status

```bash
# Container status
docker compose ps

# View logs
docker compose logs -f tileserver
docker compose logs -f valhalla
docker compose logs -f nominatim

# Test tileserver (should return a PNG)
curl -o test-tile.png http://localhost:8081/styles/grayscale/10/205/391.png

# Test Valhalla
curl http://localhost:8002/status

# Test Nominatim
curl "http://localhost:8080/search?q=Denver&format=json"
```
